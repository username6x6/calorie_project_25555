# Предсказание калорийности блюд по фото и ингредиентам

Проект по построению двухмодальной нейросети, которая оценивает калорийность блюда по фотографии и списку ингредиентов. Модель комбинирует image-энкодер (`timm`) и текстовый энкодер (`transformers`), обучается на регрессию удельной калорийности и на инференсе пересчитывает предсказание в абсолютные калории через реальную массу порции.

## Цель проекта

Получить DL-модель, пригодную для интеграции в fitness- и health-приложения. Модель считается готовой к продукту при достижении **MAE < 50 ккал** на тестовой выборке.

## Внимание, для корректной работы необходимо самостоятельно загрузить фото блюд для датасета и поместить их в папку data/images. Загрузить датасет можно по ссылке: https://disk.yandex.ru/d/kz9g5msVqtahiw

## Данные

Датасет содержит фотографии блюд, список ингредиентов, массу порции и калорийность.

```
data/
├── images/
│   └── {dish_id}/
│       └── rgb.png           # фотография блюда
├── dish.csv                  # dish_id, total_calories, total_mass, ingredients, split
├── ingredients.csv           # id, ingr
└── dish_prepared.csv         # результат EDA: ID заменены на названия, deprecated вычищен
```

**Столбцы `dish.csv`:**

- `dish_id` — ID блюда
- `total_calories` — целевая переменная
- `total_mass` — масса порции в граммах
- `ingredients` — строка вида `ingr_0000000122;ingr_0000000026;..`
- `split` — `train` или `test`

**Столбцы `ingredients.csv`:**

- `id` — ID ингредиента
- `ingr` — название ингредиента

В ходе EDA технические ID в `ingredients` заменены на читаемые названия из `ingredients.csv`. Результат сохранён в `dish_prepared.csv`, с которым дальше работают `dataset.py` и `utils.py`.

## Подход

### Архитектура

Двухмодальная модель `DishCalorieModel`:

- **Image-энкодер**: `resnet18` из `timm`, предобучен на ImageNet, `num_classes=0` (убираем стандартный классификатор). Параметры заморожены.
- **Текстовый энкодер**: `distilbert-base-uncased` из `transformers`. Разморожен, дообучается.
- **Проекции**: два линейных слоя, приводящие выходы энкодеров к общему пространству размерности `PROJECTION_DIM`.
- **Регрессионная голова**: `Sequential(ReLU, Dropout, Linear, ReLU, Dropout, Linear(_, 1))` без активации на выходе.

Выход модели — **удельная калорийность (cal/g)**, а не абсолютные калории. На инференсе предсказание умножается на реальную массу порции: `pred_cal = pred_per_g * mass`.

### Почему удельная калорийность

Разделение задачи «что за блюдо» и «сколько его по объёму» упрощает обучение: модель учит свойство блюда (калорий на грамм), которое не зависит от размера порции. На инференсе масса используется как множитель. По литературе (Nutrition5k) использование ground-truth массы даёт большой прирост качества. Лосс и метрика при этом считаются в абсолютных калориях, чтобы соответствовать целевой метрике проекта.

### Обучение

- **Loss**: `nn.L1Loss()` — напрямую оптимизирует MAE.
- **Метрика**: `torchmetrics.MeanAbsoluteError`, дополнительно RMSE и R2 на валидации.
- **Gradient clipping**: `max_norm = 1.0`.
- **Early stopping**: `patience = 5` эпох без улучшения test MAE.
- **Batch size**: 4.
- **Воспроизводимость**: фиксированный seed для `random`, `numpy`, `torch`.

## Результаты

Итоговые метрики на тестовой выборке (507 примеров):

| Метрика | Значение |
|---|---|
| **MAE** | **38.75 ккал** |
| RMSE | 69.01 ккал |
| R2 | 0.894 |

Целевая метрика **MAE < 50 достигнута**.

Лучший чекпоинт — эпоха 18. Дальше начинается лёгкое переобучение: train MAE продолжает падать, test MAE растёт.

## Что сработало

Промежуточные эксперименты показали, что наилучший результат даёт комбинация трёх решений:

| Конфигурация | Best test MAE |
|---|---|
| Разморожены оба энкодера, абсолютные калории | 63.50 |
| Заморожены оба энкодера | 82.22 |
| **Разморожен текст + удельные калории + аугментации** | **38.75** |

- **Разморозка текстового энкодера** критична: `distilbert` без fine-tuning даёт слабый [CLS]-эмбеддинг для коротких фраз вида «soy sauce, garlic, white rice».
- **Удельная калорийность** убирает шум от оценки размера порции.
- **`RandomResizedCrop` и `ColorJitter`** дают устойчивость к разным условиям съёмки.

## Анализ ошибок

Топ-5 блюд с наибольшей абсолютной ошибкой (см. `notebook.ipynb`, раздел «Валидация») показывают типичные паттерны:

1. **Нетипичный размер порции** относительно состава. Масса участвует в предсказании как множитель, поэтому редкие сочетания «лёгкий состав + большая масса» дают большую ошибку.
2. **Редкие или смешанные ингредиенты.** Супы, рагу, карри плохо читаются и по фото, и по списку ингредиентов: `distilbert` не всегда имеет в словаре специфические названия (`gochujang`, `tempeh`, `tahini`).
3. **Качество фотографии.** Размытие, тёмное освещение, посторонние объекты на кадре ведут к предсказаниям, близким к среднему по датасету.

## Ограничения

- Модель обучена на конкретном датасете и не гарантирует качество на фотографиях с другой кухни, другим освещением или нестандартной сервировкой.
- Предсказание опирается на ground-truth массу порции. В реальном приложении масса обычно неизвестна и её пришлось бы оценивать отдельно.
- Текстовый энкодер обучен на английском корпусе — для русского языка потребуется замена модели на `rubert-tiny` или аналог.
- Инференс требует GPU для комфортной скорости, на CPU каждая фотография обрабатывается секунды.
